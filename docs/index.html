TL;DR — The Three Questions We Ask and the Five Building Blocks That Emerge

Inspired by recent work showing that frontier LLMs can directly read and edit the weights of small game policies and 0.8B language models [Takehi et al., 2026], our goal in this work is to answer three questions for audio models:

  1. Can an LLM directly write and fix the weights of audio models in a Python sandbox without running gradient descent (0 backward passes)?
  2. Where is the scaling boundary as model size grows 100×—from a 318M-parameter Audio Deepfake Detector (Wav2Vec2-XLS-R-300M + AASIST) to a 32.4B-parameter Speech Recognition model (NVIDIA-Nemotron-3.5-Transcribe-30B-A4B)?
  3. Can an LLM also directly compress audio model weights in a single forward pass without losing accuracy?

Across both tasks, we find that weight-space programming follows the exact same five first-principles building blocks (released in our open-source audiowsp harness):

  • Block 1 — Profiling Weight Sensitivity to Audio Augmentations: Feed the model the exact same recording as an original .WAV, a lossy social-platform .MP3, and an 8 kHz telephone call, and measure which hidden-layer neurons shift when only the audio compression changes.
  • Block 2 — Removing Augmentation Sensitivity Without Hurting Task Performance: Because the neurons sensitive to audio compression also carry 22.1% of the task signal, deleting them directly hurts accuracy. Making the edit direction strictly 90° perpendicular to the task direction removes compression sensitivity with 0.0% loss of task performance.
  • Block 3 — Increasing Context Across Layers and Time Frames (Multi-Tapping): Instead of reading only the final layer at a single frame \(h_t\), connect earlier layers and adjacent time frames \([h_{t-1}, h_t, h_{t+1}]\) so the readout weights can detect rapid frame-to-frame changes.
  • Block 4 — Finding the Optimal Weights in One Forward Pass: Multi-epoch gradient descent (SGD / AdamW) learns dataset compression shortcuts. Our One-Forward-Pass Optimizer locks sensitivity to those shortcuts to zero and solves for the optimal weights in 0.19 seconds.
  • Block 5 — Compressing Audio Model Weights: Compress weight matrices in a single forward pass by preserving both average activation energy and frame-to-frame changes, shrinking our 318M deepfake detector to 86.8M (3.66× smaller) and shrinking Wav2Vec2-Large ASR from 315M to 142M (2.23× smaller).

Block 1: Profiling Weight Sensitivity to Audio Augmentations

An audio model's weights should respond to what is spoken (or whether a voice is real or synthetic)—not whether the audio file was uploaded to a social platform as an .MP3 or transmitted over a telephone call.

Why did the model's output break on the third file even though the words and speaker are identical? Because when we subtract the hidden-layer activations of the original studio file from the telephone or MP3 file at every time frame \(t\),

$$\Delta H_t = H_t(\text{Augmented Audio}) - H_t(\text{Original Studio Audio})$$

the hidden neurons in Layer 20 shift by 11.1% on the social-platform audio and by 34.4% on the telephone call! That difference \(\Delta H_t\) is a direct measurement of the model's weight sensitivity to audio augmentations.

Block 2: Removing Augmentation Sensitivity Without Hurting Task Performance

In Block 1, we measured how the hidden neurons shift when an audio file is compressed (\(\Delta H_t\)). Now, how do we edit the layer's weight matrix \(W\) so it stops reacting to \(\Delta H_t\) without hurting the main task?

First, let's be completely concrete about what a "direction" in a hidden layer means:

  • In Wav2Vec2 Layer 20, each audio frame is a list of \(1,024\) numbers (a vector in \(\mathbb{R}^{1024}\)).
  • How we get the Augmentation Sensitivity Direction (\(\vec{v}_{\text{aug}}\)): We take the difference vectors \(\Delta H_t = H_t(\text{Telephone}) - H_t(\text{Studio})\) across our practice clips and compute their top principal component (the top singular vector from Singular Value Decomposition, SVD). This unit vector \(\vec{v}_{\text{aug}} \in \mathbb{R}^{1024}\) points in the exact direction that telephone/MP3 compression pushes the neurons.
  • How we get the Task Direction (\(\vec{v}_{\text{task}}\)): On the same practice clips, we take the average hidden vector of Fake voices minus the average hidden vector of Real voices, \(\vec{v}_{\text{task}} = \frac{\mu_{\text{fake}} - \mu_{\text{real}}}{\|\mu_{\text{fake}} - \mu_{\text{real}}\|_2}\) (or for ASR, the top singular directions of the phoneme readout head). This unit vector points in the direction the model uses to solve the task.

Here is the catch: when we compute the dot product between \(\vec{v}_{\text{aug}}\) and \(\vec{v}_{\text{task}}\) in Layer 20, it is not zero—it is \(\vec{v}_{\text{aug}} \cdot \vec{v}_{\text{task}} = 0.47\)! That means \(22.1\%\) of the augmentation vector points along the task direction.

Why We Subtract the Overlap First (Gram-Schmidt Orthogonalization):
If we naively delete \(\vec{v}_{\text{aug}}\) from the weight matrix via \(W_{\text{naive}} = W(I - \vec{v}_{\text{aug}}\vec{v}_{\text{aug}}^T)\), we also delete \(22.1\%\) of \(\vec{v}_{\text{task}}\)—causing clean studio deepfake error (ASVspoof 2019 EER) to jump from 0.22% to 0.89% (4× worse!).

Instead, we subtract the overlapping part first: $$\vec{u}_{\perp} = \vec{v}_{\text{aug}} - \underbrace{\left(\vec{v}_{\text{aug}} \cdot \vec{v}_{\text{task}}\right)}_{0.47} \vec{v}_{\text{task}}, \qquad \hat{u}_{\perp} = \frac{\vec{u}_{\perp}}{\|\vec{u}_{\perp}\|_2}$$ Now \(\hat{u}_{\perp} \cdot \vec{v}_{\text{task}} = 0\) (they are strictly 90° perpendicular). When we edit the weights using \(\hat{u}_{\perp}\), $$W_{\text{edited}} = W \left(I - \gamma \, \hat{u}_{\perp} \hat{u}_{\perp}^T\right)$$ multiplying \(W_{\text{edited}}\) by \(\vec{v}_{\text{task}}\) gives \(W(\vec{v}_{\text{task}} - 0) = W\vec{v}_{\text{task}}\)—so 100.0% of the task signal is preserved!

Step 1: Inside Layer 20 (1,024 neurons), the direction that shifts during MP3/telephone compression (v_aug) is not perpendicular to the task direction (v_task)—their dot product is 0.47.

Filtering Noisy Channels by Signal-to-Noise Ratio: When we also fit a linear bridge \(\Delta W\) in Speech Recognition to restore clean hidden states \(H_{\text{clean}}\) from noisy states \(H_{\text{noisy}}\), trying to reconstruct all \(1,280\) Conformer channels equally fails because in \(1,184\) of those channels, background noise variance \(\Sigma_{\text{noise}}\) is larger than clean speech variance \(\Sigma_{\text{clean}}\). By sorting the channels by their exact Signal-to-Noise Ratio (\(\Sigma_{\text{clean}}\vec{v}_k = \lambda_k \Sigma_{\text{noise}}\vec{v}_k\), known as Generalized Eigenvalue Decomposition or GEVD) and keeping only the top 96 channels where Clean Speech Power > Noise Power (\(\lambda_k > 1\)), 4-dataset noisy ASR Word Error Rate drops from 8.09% (Unedited) and 7.81% (Keep All 1,280) down to 6.87%.

Block 3: Increasing Context Across Layers and Time Frames (Multi-Tapping)

In an unedited audio model, the final readout layer only looks at the final layer (Layer 24) at a single point in time (\(h_t\)). That creates two blind spots:

  1. Why 1 Layer Is Not Enough (Connecting Earlier Layers): By the time audio reaches Layer 24, the network has smoothed away fine-grained pitch, phase, and formant details that were present in earlier layers (such as Layers 8 and 16).
  2. Why 1 Time Frame Is Not Enough (Connecting Adjacent Frames \([h_{t-1}, h_t, h_{t+1}]\)): A single frame \(h_t\) is a static snapshot—it cannot tell how fast the audio is changing from one millisecond to the next. When we connect the previous frame \(h_{t-1}\) and next frame \(h_{t+1}\) into the weight matrix alongside \(h_t\), the weights can directly compute:
    • Frame-to-Frame Speed (\(\frac{1}{2}(h_{t+1} - h_{t-1})\)): Spikes sharply at rapid consonant bursts (/p/, /t/, /k/) that room echo otherwise blurs.
    • Frame Acceleration (\(h_{t+1} - 2h_t + h_{t-1}\)): Spikes at synthetic vocoder frame boundaries (where neural vocoders stitch \(20\text{ ms}\) audio chunks together).
  3. Scoring Anomalies on One Side Only (\(\max(0, z)^2\)): Suppose real human voices sit around standardized score \(z = 0\) (spanning \(-2.5\) to \(+1.5\)) and synthetic deepfakes shift to the positive side (\(z > +1.5\)). If we square \(z\) directly (\(z^2\)), a real human speaking expressively on the negative tail at \(z = -2.5\) gets squared to \((-2.5)^2 = +6.25\) and falsely flagged as a deepfake! Clipping negative values to zero first via \(\log(1 + \max(0, z)^2)\) gives 0.0 penalty across the entire real-human side (\(z \le 0\)) while quadratically boosting deepfake anomalies on the positive side (\(z > 0\)).

Block 4: Finding the Optimal Weights in One Forward Pass

Now that we have our features and our augmentation sensitivity vectors, how do we compute the best weights \(W\)?

Instead of abstract equations, step through the interactive 3-scene walkthrough below on real audio examples to see why running 25 epochs of gradient descent (SGD or AdamW) learns the wrong weights—and how our One-Forward-Pass Optimizer (OFP) lands directly at the optimal weights in 0.19 seconds:

Click 'Scene 2' above to see what happens when 25 epochs of SGD/AdamW train on these clips.

The Exact Closed-Form Equation Behind Scene 3: Because the readout layer \(y = \Phi W\) is linear in the weights \(W\), the squared error objective with an \(\ell_2\) penalty \(\lambda \|W\|_2^2\) is a smooth bowl with a single exact global minimum. In one forward pass (`torch.inference_mode()`), we collect:

  1. The feature correlation matrix \(A = \Phi^T \Pi \Phi + \lambda I\) (where \(\Pi = \text{diag}(\pi_i)\) gives \(1.5\times\) higher weight to hard boundary clips where the base model is uncertain),
  2. The target separation vector \(\vec{d}_{\text{task}}\), and
  3. The paired augmentation difference vectors \(C_{\text{aug}} = \mathbb{E}[\Phi(\text{MP3}) - \Phi(\text{WAV})]\).
Solving for the weights \(W\) that minimize error subject to the hard constraint \(C_{\text{aug}}^T W = 0\) (zero sensitivity to audio compression) has an exact one-line solution: $$W_{\text{OFP}} = A^{-1}\vec{d}_{\text{task}} - A^{-1}C_{\text{aug}}\left(C_{\text{aug}}^T A^{-1} C_{\text{aug}}\right)^{-1} C_{\text{aug}}^T A^{-1}\vec{d}_{\text{task}}$$ On 1× H100 GPU across \(D = 122,880\) features, this matrix equation solves in 0.19 seconds and achieves 4.12% Equal Error Rate across 4 unseen deepfake datasets—compared to 6.95% Equal Error Rate after 25 epochs (12.40 seconds) of AdamW backpropagation.

Block 5: Compressing Audio Model Weights

Finally, can we use the same one-forward-pass philosophy to compress the internal weight matrices of an audio model?

Suppose we want to compress a \(1024 \times 1024\) weight matrix \(W\) inside Wav2Vec2 down to rank \(r = 384\) (replacing one large matrix with two thin matrices \(U_r V_r^T\)).

  • Why Standard SVD Weight Compression Hurts Audio Models: Standard Singular Value Decomposition (SVD) or activation-weighted SVD (ASVD) keeps the directions with the largest average static energy \(\text{Cov}(Z_t)\). In audio, slow background hum and steady vowels have huge static energy, whereas fast consonant bursts (/p/, /t/, /k/) last only \(10\text{–}20\text{ ms}\)—so they have small static energy but large frame-to-frame change \((Z_t - Z_{t-1})\)! Standard SVD throws away those fast-changing directions, cutting consonant burst peaks by -42% (red shaded region below).
  • How Transition-Preserving SVD Fixes It in One Forward Pass: Instead of compressing using static covariance alone, we weight the SVD by static energy plus \(2\times\) frame-to-frame transition energy: $$\Sigma_{\text{joint}} = \text{Cov}(Z_t) + 2.0 \, \text{Cov}(Z_t - Z_{t-1})$$ This protects every fast-changing consonant and vocoder-click direction from truncation, preserving 99.1% of the sharp transition peaks!
