Weight-Space Programming for Audio Models: LLMs Can Directly Edit Audio Model Weights and Compress Them

Can an LLM directly edit the weights of audio models to improve performance without backward passes, scale 100× from 318M to 32.4B parameters, and compress weights in a single forward pass?

TL;DR

Inspired by recent work on Weight-Space Programming (WSP) [Takehi et al., 2026], we investigate three questions for audio models:

  1. Can an LLM directly edit the weights of audio models to improve performance without backward passes?
  2. Understand scalability of Weight-Space Programming (WSP) as model size grows 100×—from a 318M-parameter Audio Deepfake Detector (Wav2Vec2-XLS-R-300M + AASIST) to a 32.4B-parameter Speech Recognition model (NVIDIA-Nemotron-3.5-Transcribe-30B-A4B)?
  3. Can an LLM directly compress audio model weights in a single forward pass without losing accuracy?

How WSP Discovered the 5 Building Blocks (and Why We Built the Harness): We gave an LLM agent a Python sandbox to iteratively inspect model errors on practice audio, write weight-editing code, and check the result in a forward pass (iterating through 23 rounds p01 → p23 on Deepfake Detection and 8 rounds v1 → v8 on Speech Recognition). Across both tasks, the agent repeatedly converged on the exact same five building blocks. We packaged these five blocks into our open-source audiowsp harness so any agent or researcher can apply them directly:

BLOCK 1 Benchmarking Weight Sensitivity to Audio Augmentations Measure how hidden neurons change when the same audio is compressed or filtered. BLOCK 2 Removing Augmentation Sensitivity Without Drop in Performance Edit weights at a 90° angle to the task direction so accuracy never drops. BLOCK 3 Increasing Context Across Layers (Multi-Tapping) Connect earlier layers and adjacent frames into the output layer. BLOCK 4 Finding the Optimal Weights in One Forward Pass Lock sensitivity to dataset shortcuts to zero and solve in 1 pass. BLOCK 5 Compressing Audio Model Weights Shrink 318M → 86.8M (3.66×) and 315M → 142M (2.23×) in 1 pass.

How Block 1 Benchmarks Sensitivity Across Augmentations: For any practice audio clip \(x_{\text{studio}}\), we generate paired augmented copies \(\tilde{x}_{\text{aug}}\) with the exact same speaker, words, and timing, and record the difference in hidden-layer activations \(\Delta H_t = H_t(\tilde{x}_{\text{aug}}) - H_t(x_{\text{studio}})\). In addition to MP3 and 8 kHz telephone filtering shown above, the audiowsp harness benchmarks sensitivity across neural codecs (Encodec), room reverberation (RIR), additive background noise (AWGN / babble), and volume/gain shifts.

Block 2: Removing Augmentation Sensitivity Without Drop in Performance

Block 1 of WSP benchmarked how the hidden neurons change when an audio file is compressed (\(\Delta H_t\)). How do we edit the layer's weight matrix \(W\) so it ignores \(\Delta H_t\) without any drop in task performance?

First, let's define what a "direction" in a hidden layer means:

  • In Wav2Vec2 Layer 20, each audio frame is represented by a list of 1,024 numbers (a vector in \(\mathbb{R}^{1024}\)).
  • The Augmentation Sensitivity Direction (\(\vec{v}_{\text{aug}}\)): We take the activation differences \(\Delta H_t = H_t(\text{Telephone}) - H_t(\text{Studio})\) across practice clips and take their top singular vector (via Singular Value Decomposition, SVD). This unit vector \(\vec{v}_{\text{aug}}\) points in the direction that telephone/MP3 compression pushes the neurons.
  • The Task Direction (\(\vec{v}_{\text{task}}\)): On the same practice clips, we compute the average vector of Fake voices minus the average vector of Real voices, \(\vec{v}_{\text{task}} = \frac{\mu_{\text{fake}} - \mu_{\text{real}}}{\|\mu_{\text{fake}} - \mu_{\text{real}}\|_2}\). This unit vector points in the direction the model uses to solve the task.

Why Naive Removal Hurts Performance: When we take the dot product between \(\vec{v}_{\text{aug}}\) and \(\vec{v}_{\text{task}}\) in Layer 20, it is \(\vec{v}_{\text{aug}} \cdot \vec{v}_{\text{task}} = 0.47\)—meaning the two directions share 22.1% of their energy. If we naively delete \(\vec{v}_{\text{aug}}\) from the weights, we also erase 22.1% of the task direction, making clean studio deepfake error 4× worse (0.22% → 0.89% EER).

By subtracting that overlap first (\(\vec{u}_{\perp} = \vec{v}_{\text{aug}} - 0.47\,\vec{v}_{\text{task}}\)), our edit direction \(\hat{u}_{\perp}\) is at an exact 90° angle to \(\vec{v}_{\text{task}}\). Editing the weights via \(W_{\text{new}} = W(I - \gamma \hat{u}_{\perp}\hat{u}_{\perp}^T)\) removes compression sensitivity with 0.0% loss of task signal:

Block 3: Increasing Context Across Layers (Multi-Tapping)

In a standard audio model, the output layer (last layer) only reads the final transformer block (Layer 24) at a single frame \(h_t\). Why is reading only Layer 24 not enough?

Look at the measured layer-by-layer chart below from Wav2Vec2-XLS-R (Layers 0 to 24):

  • Green Curve (Fine-Grained Pitch & Vocoder Phase Signal): Peaks in the early and middle layers (Layers 8–12) and drops sharply by Layer 24, because the final layers of a speech model are trained to smooth out acoustic variations and focus on words.
  • Blue Curve (High-Level Word & Phonetic Context): Peaks in the deep layers (Layers 20–24).

In addition to connecting earlier layers into the output layer, we also connect adjacent frames \([h_{t-1}, h_t, h_{t+1}]\) so the output layer can measure frame-to-frame speed \(\frac{1}{2}(h_{t+1} - h_{t-1})\)—which spikes during rapid stop consonants (such as the crisp "p", "t", and "k" sounds in speech, denoted /p/, /t/, /k/)—and we score anomalies on one side only via \(\log(1 + \max(0, z)^2)\) so real human voices on the negative tail (\(z \le 0\)) receive zero false-alarm penalty.

Block 4: Finding the Optimal Weights in One Forward Pass

Why does training with 25 epochs of gradient descent (SGD or AdamW) learn the wrong weights on audio datasets, and how does our One-Forward-Pass Optimizer (OFP) find the optimal shortcut-free weights in a single pass?

Click through Steps 1, 2, and 3 in the interactive 2D feature-space plot below:

Blue Circles = Clean Real Voice | Red X = Fake Voice. Click Step 2 to see how 25-epoch SGD tilts the boundary.

Why 1 Forward Pass Is Enough: In a single forward pass (`torch.inference_mode()`), we collect the feature correlation matrix \(A = \Phi^T \Pi \Phi + \lambda I\), the task separation vector \(\vec{d}_{\text{task}}\), and the vertical compression shift \(C_{\text{aug}} = \mathbb{E}[\Phi(\text{MP3}) - \Phi(\text{WAV})]\). Solving for the weights \(W\) with sensitivity to \(C_{\text{aug}}\) locked to zero (\(C_{\text{aug}}^T W = 0\)) has an exact closed-form solution: $$W_{\text{OFP}} = A^{-1}\vec{d}_{\text{task}} - A^{-1}C_{\text{aug}}\left(C_{\text{aug}}^T A^{-1} C_{\text{aug}}\right)^{-1} C_{\text{aug}}^T A^{-1}\vec{d}_{\text{task}}$$ This single pass reduces sensitivity to compression shortcuts to 0.0 and achieves 4.12% Equal Error Rate across 4 unseen deepfake datasets (vs. 6.95% for 25-epoch AdamW).

Block 5: Compressing Audio Model Weights

Can we also compress an audio model's weight matrices in a single forward pass without losing accuracy?

When compressing a weight matrix \(W\) using standard Singular Value Decomposition (SVD), the algorithm keeps directions with the largest average static energy \(\text{Cov}(Z_t)\). In audio, steady vowels and background hum have large static energy, whereas stop consonants (such as the crisp "p", "t", and "k" sounds in speech, denoted /p/, /t/, /k/) last only \(10\text{–}20\text{ ms}\)—so they have small static energy but large frame-to-frame change \((Z_t - Z_{t-1})\).

Standard SVD discards those fast-changing directions, cutting stop-consonant burst peaks by -42% (red shaded area below). By compressing in the combined metric \(\Sigma_{\text{joint}} = \text{Cov}(Z_t) + 2\,\text{Cov}(Z_t - Z_{t-1})\), we preserve 99.1% of the consonant peaks while shrinking our 318M deepfake detector to 86.8M (3.66× smaller) and shrinking Wav2Vec2-Large ASR from 315M to 142M (2.23× smaller):
