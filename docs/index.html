Can an LLM directly edit the weights of audio models to improve performance without backward passes, scale 100× from 318M to 32.4B parameters, and compress weights in a single forward pass?

TL;DR

Inspired by Weight-Space Programming (WSP) [Takehi et al., 2026], we gave an LLM agent a Python sandbox to iteratively inspect audio model errors on practice clips, write direct weight-editing code, and verify the result in a single forward pass. Across both Audio Deepfake Detection and Speech Recognition, the agent converged on six reusable weight-space building blocks packaged in our open-source audiowsp harness:

BLOCK 1 Benchmarking Weight Sensitivity to Audio Augmentations Measure how hidden neurons shift when the same audio is compressed or filtered. BLOCK 2 Removing Augmentation Sensitivity Without Drop in Performance Edit weights at a 90° angle to the task direction so clean accuracy never drops. BLOCK 3 Increasing Context Across Layers Connect earlier layers and adjacent frames as a direct shortcut into the output layer. BLOCK 4 Finding the Optimal Weights in One Forward Pass Lock sensitivity to dataset shortcuts to zero and solve in 1 pass. BLOCK 5 Compressing Audio Model Weights Preserve 20 ms consonant bursts while shrinking 318M → 86.8M (3.66×) in 1 pass. BLOCK 6 Consolidating Orthogonal Speech Pathways (13.31B) Pack orthogonal speech pathways into one 13.31B file (3.78% WER, 323× RTFx).

How Block 1 Benchmarks Sensitivity Across Augmentations: For any practice audio clip \(x_{\text{studio}}\), we generate paired augmented copies \(\tilde{x}_{\text{aug}}\) with the exact same speaker, words, and timing, and record the difference in hidden-layer activations \(\Delta H_t = H_t(\tilde{x}_{\text{aug}}) - H_t(x_{\text{studio}})\). Block 2: Removing Augmentation Sensitivity Without Drop in Performance

Block 1 of WSP benchmarked how the hidden neurons change when an audio file is compressed (\(\Delta H_t\)). How do we edit the layer's weight matrix \(W\) so it ignores \(\Delta H_t\) without any drop in task performance?

First, let's define what a "direction" in a hidden layer means:

  • In Wav2Vec2 Layer 20, each audio frame is a 1,024-dimensional vector.
  • The Augmentation Sensitivity Direction (\(\vec{v}_{\text{aug}}\)): We take the activation differences \(\Delta H_t = H_t(\text{Telephone}) - H_t(\text{Studio})\) across practice clips and take their top singular vector (via Singular Value Decomposition, SVD). This unit vector \(\vec{v}_{\text{aug}}\) points in the direction that telephone/MP3 compression pushes the neurons.
  • The Task Direction (\(\vec{v}_{\text{task}}\)): On the same practice clips, we compute the average vector of Fake voices minus the average vector of Real voices, \(\vec{v}_{\text{task}} = \frac{\mu_{\text{fake}} - \mu_{\text{real}}}{\|\mu_{\text{fake}} - \mu_{\text{real}}\|_2}\). This unit vector points in the direction the model uses to solve the task.

Why Naive Removal Hurts Performance: When we take the dot product between \(\vec{v}_{\text{aug}}\) and \(\vec{v}_{\text{task}}\) in Layer 20, it is \(\vec{v}_{\text{aug}} \cdot \vec{v}_{\text{task}} = 0.47\)—meaning the two directions share 22.1% of their energy. If we naively delete \(\vec{v}_{\text{aug}}\) from the weights, we also erase 22.1% of the task direction, making clean studio deepfake error 4× worse (0.22% → 0.89% EER).

By subtracting that overlap first (\(\vec{u}_{\perp} = \vec{v}_{\text{aug}} - 0.47\,\vec{v}_{\text{task}}\)), our edit direction \(\hat{u}_{\perp}\) is at an exact 90° angle to \(\vec{v}_{\text{task}}\). Editing the weights via \(W_{\text{new}} = W(I - \gamma \hat{u}_{\perp}\hat{u}_{\perp}^T)\) removes compression sensitivity with 0.0% loss of task signal:

Weight Edit Formula W (I − γ u_perp u_perp^T) [90° Perpendicular]

Visualizing Signal-vs-Noise Channel Filtering Across 1,280 Channels

In our 32.4B Speech Recognition model (Nemotron-3.5), the Conformer encoder outputs a 1,280-dimensional vector per audio frame. How do we measure how much clean speech versus background noise each channel carries—without needing a separate speaker diarizer?

We reuse the exact same paired audio setup from Block 1:

  1. Take a clean studio utterance \(x_{\text{clean}}\) and create a noisy copy \(\tilde{x}_{\text{noisy}}\) (by adding background babble noise, room echo, or 8 kHz telephone filtering to that exact same recording).
  2. Pass both through the encoder: Because the speaker and frame timestamps are identical, \(H_{\text{clean}} = H(x_{\text{clean}})\) is the pure speech activation, and the difference \(\Delta H_{\text{noise}} = H(\tilde{x}_{\text{noisy}}) - H(x_{\text{clean}})\) is the pure noise shift inside the encoder.
  3. Compare their variance per channel: The variance of \(H_{\text{clean}}\) gives the Clean Speech Power (\(\Sigma_{\text{clean}}\), Green Bars), and the variance of \(\Delta H_{\text{noise}}\) gives the Background Noise Power (\(\Sigma_{\text{noise}}\), Red Bars).

When we sort all 1,280 eigen-channels by the ratio of Clean Speech Power to Background Noise Power (\(\Sigma_{\text{clean}}\vec{v}_k = \lambda_k \Sigma_{\text{noise}}\vec{v}_k\)), only the top 96 channels have more speech than noise (Green > Red). In the remaining 1,184 channels, noise is louder than speech (Red > Green)! Keeping only the top 96 channels when fitting the encoder-to-LLM bridge drops 4-dataset noisy Word Error Rate from 8.09% (Unedited) and 7.81% (Keep All 1,280) down to 6.87%:

Keep Top 96 Channels (Speech > Noise Cutoff) → 6.87% Noisy WER (Best!)

Block 3: Increasing Context Across Layers

In a standard pretrained audio model, the output layer (last layer) only reads the final transformer block (Layer 24) at frame \(h_t^{(24)}\). A natural question is: since Transformer blocks already have self-attention across time, shouldn't \(h_t^{(24)}\) already contain all the temporal and earlier-layer context on its own?

When we inspect the internal activations of Wav2Vec2-XLS-R and Nemotron-3.5 (with frozen backbone weights, 0 backward passes), we find two reasons why \(h_t^{(24)}\) alone loses fast transitions—and why adding a direct shortcut from earlier layers and neighboring frames into the output layer helps so much:

  1. Self-Attention Weights Are Positive (\(\alpha_{t,\tau} \ge 0\)), So They Average Rather Than Subtract: At each layer, softmax self-attention computes a weighted average \(h_t^{\text{attn}} = \sum_\tau \alpha_{t,\tau} V h_\tau\) with non-negative weights \(\alpha_{t,\tau} \ge 0, \, \sum_\tau \alpha_{t,\tau} = 1\) spanning \(300\text{–}800\text{ ms}\) (15–40 frames) to build word-level context. Because positive averaging acts as a smoothing filter across layers, 20 ms frame-to-frame sharpness drops from 0.441 at Layer 8 down to 0.305 by Layer 22 (Green curve in Figure 4A below).
  2. A Frozen Attention Layer Cannot Be Retrained to Compute \(h_{t+1} - h_{t-1}\): Without backpropagating into the 24 attention layers to rewrite their query/key matrices, the output layer only sees the smoothed vector \(h_t^{(24)}\) (Red dashed curve in Figure 4B). Providing a direct shortcut from earlier un-smoothed layers (Layers 8 & 16) and adjacent frames \((h_{t+1} - h_{t-1})\) directly into the output layer recovers the sharp 20 ms spike (Green curve in Figure 4B) in a single forward pass!

Figure 4: (A) Across Layers 0–24 of Wav2Vec2: fast 20 ms transition/vocoder signal (green, measured via frame speed \(\|\frac{1}{2}(h_{t+1}^{(l)}-h_{t-1}^{(l)})\|_2 / \|h_t^{(l)}\|_2\) and unseen-vocoder AUC on f12_7s_pk1_dev_and_nuis.npz) peaks in middle layers (L8–L14) and drops by 31% by L24, whereas linear phonetic accuracy on practice_dev (blue) rises from 49.9% to 99.4% at L24. (B) Across time, L24 alone smooths out a 20 ms burst (red dashed), while the direct shortcut from L8–L16 and \((h_{t+1}-h_{t-1})\) preserves the sharp spike (green). [Reproduce Figure 4]

In addition to connecting earlier layers into the output layer, we also connect adjacent frames \([h_{t-1}, h_t, h_{t+1}]\) so the output layer can measure frame-to-frame speed \(\frac{1}{2}(h_{t+1} - h_{t-1})\)—which spikes during rapid stop consonants (such as the crisp "p", "t", and "k" sounds in speech, denoted /p/, /t/, /k/)—and we score anomalies on one side only via \(\log(1 + \max(0, z)^2)\) so real human voices on the negative tail (\(z \le 0\)) receive zero false-alarm penalty.

Block 4: Finding the Optimal Weights in One Forward Pass

Why does training with 25 epochs of gradient descent (SGD or AdamW) learn the wrong weights on audio datasets, and how does our One-Forward-Pass Optimizer (OFP) find the optimal shortcut-free weights in a single pass?

[Audit full benchmark script: benchmarks/benchmark_fpo1_vs_backprop.py]

Why 1 Forward Pass Is Enough (Every Term & Setup Detail Defined): In a single forward pass (torch.inference_mode()), we solve the closed-form equation: $$W_{\text{OFP}} = A^{-1}\vec{d}_{\text{task}} - A^{-1}C_{\text{aug}}\left(C_{\text{aug}}^T A^{-1} C_{\text{aug}}\right)^{-1} C_{\text{aug}}^T A^{-1}\vec{d}_{\text{task}}, \qquad \text{where } A = \Phi^T \Pi \Phi + \lambda I$$
  • \(\Phi \in \mathbb{R}^{N \times D}\): The feature matrix across \(N = 12,371\) training clips (train_manifest_12k.jsonl), where each row \(\Phi_i \in \mathbb{R}^{122,880}\) is the 12-layer feature vector from Block 3 on Wav2Vec2-XLS-R-300M.
  • \(\Pi = \text{diag}(\pi_1, \dots, \pi_N) \in \mathbb{R}^{N \times N}\): A diagonal sample-weighting matrix that gives \(1.5\times\) higher weight \(\pi_i\) to hard boundary clips (where the base model is uncertain) and lower weight to easy clips.
  • \(\lambda > 0\) and \(I \in \mathbb{R}^{D \times D}\): The \(\ell_2\) regularization scalar \(\lambda\) and the \(D \times D\) identity matrix \(I\), ensuring \(A\) is invertible and keeping weight magnitudes small.
  • \(\vec{d}_{\text{task}} = \Phi^T \Pi y \in \mathbb{R}^D\): The task correlation vector between the features \(\Phi\) and the binary target labels \(y \in \{0, 1\}\).
  • \(C_{\text{aug}} = \mathbb{E}[\Phi(\tilde{x}_{\text{aug}}) - \Phi(x_{\text{clean}})] \in \mathbb{R}^{D \times J}\): The \(J\) augmentation shift vectors measured on 320 paired clean vs. MP3/Encodec/telephone/AWGN/RIR practice clips from Block 1.
Because multiplying \(W_{\text{OFP}}\) by \(C_{\text{aug}}^T\) gives \(C_{\text{aug}}^T W_{\text{OFP}} = \mathbf{0}\), sensitivity to those augmentation directions is locked to 0.0. In our head-to-head benchmark (benchmarks/benchmark_fpo1_vs_backprop.py, using identical features \(\Phi\), identical training clips, and cosine-annealed lr=1e-3, batch_size=256 for SGD/AdamW), 1-Pass OFP achieves 4.12% Macro Equal Error Rate across the 4 held-out evaluation suites (7,359 trials), compared to 6.95% for 25-epoch AdamW and 5.84% for 25-epoch AdamW with paired data augmentation.

How Is This Different From Standard Data Augmentation?

A natural question looking at Step 3 above is: if we just augment the training set with MP3 and telephone audio so the training data is balanced, wouldn't standard gradient descent (SGD / AdamW) learn the vertical boundary on its own?

When we test 25-Epoch AdamW with the exact same paired data augmentations against 1-Pass OFP, we find three fundamental differences:

  1. Average Loss Minimization vs. Exact Pairwise Cancellation (\(C_{\text{aug}}^T W = 0\)): Data augmentation adds augmented samples \((x_{\text{MP3}}, y)\) into the training loss \(\sum_i \mathcal{L}(W^T \Phi(x_i), y_i)\). Gradient descent only asks that augmented samples land on the correct side of the boundary on average—it never forces the score of \(x_{\text{MP3}}\) and \(x_{\text{WAV}}\) of the same recording to be identical! As a result, 25-epoch AdamW with data augmentation still retains residual shortcut weight (\(\|C_{\text{aug}}^T W\| = 0.28\), yielding 5.84% Unseen EER), whereas OFP enforces the hard equality \(C_{\text{aug}}^T W = \mathbf{0}\) (0.0000 shortcut leakage, yielding 4.12% Unseen EER).
  2. 320 Paired Clips in 1 Pass vs. Re-Augmenting the Entire Dataset Across 25 Epochs: To balance a dataset of \(N\) clips across \(J = 10\) audio augmentations for gradient descent, you must run \(25 \text{ epochs} \times 10 \text{ augmentations} = \mathbf{250\times}\) more forward and backward passes. Because the augmentation shift \(C_{\text{aug}} = \mathbb{E}[\Phi(\tilde{x}) - \Phi(x)]\) spans a low-dimensional subspace, OFP estimates \(C_{\text{aug}}\) from just 220–320 paired practice clips in a single forward pass.
  3. Works on Unlabeled Audio: Notice that the constraint vector \(C_{\text{aug}} = \mathbb{E}[\Phi(\tilde{x}_{\text{MP3}}) - \Phi(x_{\text{WAV}})]\) does not use the class label \(y\) at all. Any unlabeled speech recording can be compressed in a single forward pass to measure \(C_{\text{aug}}\) and lock out new codec or channel directions without needing labeled training data for that channel.

Block 5: Compressing Audio Model Weights

Can we also compress an audio model's weight matrices in a single forward pass without losing accuracy?

When compressing a weight matrix \(W\) using standard Singular Value Decomposition (SVD), the algorithm keeps directions with the largest average static energy \(\text{Cov}(Z_t)\). In audio, steady vowels and background hum have large static energy, whereas stop consonants (such as the crisp "p", "t", and "k" sounds in speech, denoted /p/, /t/, /k/) last only \(10\text{–}20\text{ ms}\)—so they have small static energy but large frame-to-frame change \((Z_t - Z_{t-1})\).

Standard SVD discards those fast-changing directions, cutting stop-consonant burst peaks by -42% (red shaded area below). By compressing in the combined metric \(\Sigma_{\text{joint}} = \text{Cov}(Z_t) + 2\,\text{Cov}(Z_t - Z_{t-1})\), we preserve 99.1% of the consonant peaks while shrinking our 318M deepfake detector to 86.8M (3.66× smaller) and shrinking Wav2Vec2-Large ASR from 315M to 142M (2.23× smaller):

Block 6: Consolidating Orthogonal Speech Pathways Into a Single 13.31B Checkpoint (323× RTFx)

When we compare hidden states and weight matrices across open-weights speech architectures on practice_dev and official validation splits, two observations let us package a single standalone 13.31B checkpoint (ishiki-labs/ishiki-asr-1.0, one 24.79 GiB model.safetensors file with zero external model dependencies) that lowers average Word Error Rate across all 10 public benchmarks on the Hugging Face Open ASR Leaderboard from 4.69% (33.7B Nemotron-3.5-30B) and 4.40% (best prior single open-weights model) to 3.78% at 323.4× corpus RTFx on a single H100 GPU:

  1. Different Models Learn Complementary, Nearly Perpendicular Features (88.1° Apart): When the same base model (Qwen3-ASR-1.7B) is adapted for conversational speech (\(\Delta W_{\text{conv}}\)) versus noisy/accented speech (\(\Delta W_{\text{noisy}}\)), their weight updates have cosine similarity \(\cos\theta = 0.033\) (\(88.1^\circ\)—nearly perpendicular). Combining perpendicular weight-space surgery, zero-distortion validation WiSE-FT, and BatchNorm-frozen Conformer/Q-Former adaptation aligns complementary dense pathways (Ventral & Ventral-Noise 4.70B, Spontaneous 2.73B, Meeting 2.31B, Dorsal 2.07B, Broadband Whisper + Transducer Parakeet 1.50B) inside one self-contained 13.31B checkpoint—eliminating 60.3B of multi-MoE backbones entirely.
  2. Acoustic-Gated Cascaded Routing & Word-Posterior Confusion Networks (`323.4×` RTFx): A 0.27M-parameter IshikiAcousticPathwayGate resolves unambiguous utterances immediately in Stage 1 (reaching 423.6× RTFx on LibriSpeech clean and 348.1× RTFx on SPGISpeech) and routes only contested utterances through Cochran ratio-calibrated spectral competence and word-posterior confusion-network decoding, delivering 3.78% 10-dataset mean WER at 323.4× corpus RTFx from raw audio alone with zero dataset flags:
